# Native trust HTTP adapter and persistent cache worker

TrustRoutes mounts list/state/reset endpoints with the existing origin, account, deleted-user and body-parser boundaries. Trust remains shared across authenticated accounts exactly as in the reference; no new role policy is introduced. Encoded action identifiers are decoded once and bound as SQL parameters. The default standalone server does not mount these routes.

TrustWorker uses the existing bounded DatabaseWorker queue and runs all SQLite operations on its dedicated thread. A private shared TrustCache keeps in-memory state alive across temporary repository facades. This preserves cache reads after external database changes and retained reset/approval state after failed writes. Memory mode returns cache insertion order; database list reads continue to expose persisted rows. Worker close/drain, cancellation and admission follow the already tested database worker. Public concurrent trust jobs serialize rather than losing increments.

Real Fastify/native HTTP comparisons cover memory and database modes, unknown actions, thresholds and reverts, reset effects, global lists, encoded path identities, cookie/bearer auth, missing users, foreign origins, malformed bodies, stale cached rows and trigger-induced write failures. A separate test exercises thirty concurrent approval jobs and shared shutdown.
