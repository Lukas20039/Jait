# Native provider snapshot and OpenCode credential helpers

ProviderSnapshotCache implements a sixty-second wall-clock TTL, fresh cached values, stale immediate returns with detached refresh, cold/forced waits, warm-up, in-flight sharing, invalidation that preserves active work and ordered snapshots. Availability failures become installed=false. Auth probe failures preserve source metadata while making authentication unknown and adding the source diagnostic. Explicit provider types override metadata types; null auth falls back to metadata. Native probes are typed async callbacks, with no provider CLI execution in this slice. Snapshot results use shared immutable Arc values. Registry/callback panics release in-flight state as errors instead of wedging future refreshes.

OpenCode credential storage uses explicit XDG/home/system-home paths, ECMAScript trim, UTF-8 replacement, object-only JSON validation, fixed preservation errors, nonthrowing existence checks and atomic random exclusive temporary files. Updates preserve other connections, use 0700 newly created directories and 0600 files, then rename and clean up. This is the Linux filesystem adapter; Windows path/permission evidence remains unverified. Run synchronous filesystem operations through a blocking lane in future provider integration. Only synthetic keys and project-local isolated directories are used in tests.

The real TypeScript implementations are exercised with controlled clocks, deferred probes, concurrent calls, stale/fresh boundary checks, failures, registry retry, invalidation, empty snapshots and mutable provider metadata. Filesystem contracts compare exact saved JSON, invalid file preservation, missing files, malformed JSON, array/null rejection, directory errors, invalid UTF-8, cleared keys, file permissions and no leftover temporary files. Generic system I/O messages are reduced to an error category; the credential preservation diagnostic is checked separately.
